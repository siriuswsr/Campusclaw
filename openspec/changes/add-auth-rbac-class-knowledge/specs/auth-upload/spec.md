## Purpose

定义教学材料的班级隔离存储与访问模型：教师可上传材料至知识库（文件存磁盘 + SQLite 元数据），所有材料查询 MUST 在服务端按当前用户所属班级强制过滤，跨班访问被拒绝，上传后本班材料列表 MUST 可查到该记录。

## ADDED Requirements

### Requirement: 教师上传材料至知识库

系统 SHALL 允许教师上传教学材料文件；上传时 MUST 将文件写入服务端磁盘目录，并在数据库中创建元数据记录；上传完成后本班材料列表查询 MUST 能查到该记录。

#### Scenario: 教师成功上传

- **WHEN** 角色为 `teacher` 的用户上传文件并附带材料标题
- **THEN** 系统将文件写入磁盘上传目录，在数据库写入元数据记录（标题、班级 ID、上传者 ID、文件路径、上传时间），返回材料 ID

#### Scenario: 上传后本班列表可查

- **WHEN** 教师上传一份材料后，本班任意用户（教师或学生）请求材料列表
- **THEN** 列表结果中包含刚上传的材料记录

#### Scenario: 学生上传被拒

- **WHEN** 角色为 `student` 的用户调用材料上传接口
- **THEN** 系统返回 403 Forbidden，不写入磁盘或数据库

### Requirement: 班级数据边界

系统 MUST 将班级作为数据访问边界：所有材料查询 MUST 在服务端按当前用户所属班级过滤；MUST NOT 依赖前端隐藏按钮或 URL 参数约束访问；A 班用户访问 B 班材料 MUST 被拒绝。

#### Scenario: 查询本班材料列表

- **WHEN** A 班用户请求材料列表
- **THEN** 系统仅返回 A 班材料记录，不返回其他班级任何记录

#### Scenario: 跨班访问单条材料

- **WHEN** A 班用户请求 B 班某条材料的元数据
- **THEN** 系统返回 404（或 403），不返回该材料内容或元数据

#### Scenario: 跨班下载文件

- **WHEN** A 班用户请求下载 B 班材料文件
- **THEN** 系统拒绝并返回 403 或 404，不返回下载链接或文件流

#### Scenario: 服务端强制过滤

- **WHEN** 任意用户发起材料查询
- **THEN** 数据库查询语句的 WHERE 条件中 MUST 包含该用户所属班级 ID 过滤，而非在应用层从全量数据中筛选后裁剪

### Requirement: 材料元数据存储

系统 MUST 将材料的可查询属性存储于关系数据库（SQLite），文件二进制存储于服务端磁盘；元数据记录 MUST 包含班级 ID 字段作为隔离依据，并建立索引以支持按班级过滤查询。

#### Scenario: 元数据完整性

- **WHEN** 教师上传一份材料
- **THEN** 数据库元数据记录包含 `class_id`、`uploader_id`、`file_path`、`title`、`created_at`，缺一不可

#### Scenario: 按班级过滤查询

- **WHEN** 查询某班材料列表
- **THEN** 数据库查询在 WHERE 条件中包含 `class_id` 过滤，且 `class_id` 字段存在索引

### Requirement: 文件存储与访问

系统 MUST 将上传的材料文件存储于服务端指定目录，文件路径 MUST 不可由客户端直接指定；下载时 MUST 先校验当前用户对该材料的班级访问权限，再返回文件流。

#### Scenario: 下载本班材料

- **WHEN** 本班用户请求下载本班材料
- **THEN** 系统校验权限通过后返回文件流，HTTP 200

#### Scenario: 跨班下载被拒

- **WHEN** A 班用户请求下载 B 班材料
- **THEN** 系统返回 403 或 404，不返回文件流或下载链接

#### Scenario: 文件路径不可枚举

- **WHEN** 客户端尝试通过构造文件路径直接访问磁盘文件
- **THEN** 系统 MUST 通过受控下载端点提供文件，不暴露静态文件目录的直接 HTTP 访问

#### Scenario: health 仅做存活判定，不混入数据库探活

- **WHEN** 数据库文件不可读或被删除（进程仍在运行）
- **THEN** `GET /health` MUST 仍返回 HTTP 200
- **AND** MUST NOT 因为数据库故障返回 503
- **NOTE** 数据库不可用时业务接口（如材料列表、上传）应返回 503，不得把已登录用户判为会话失效 401

---

### Requirement: 登录限流与失败响应同形

为防止账号枚举与暴力破解，系统 MUST 对登录施加基础限流；被限流、账号不存在、口令错误三类登录失败 MUST 返回一致的状态码与响应体。

#### Scenario: 被限流时响应与口令错误不可区分

- **WHEN** 同一 IP 或用户名在短时间内发起超过阈值的登录请求
- **THEN** 系统 MUST 拒绝后续登录
- **AND** 响应 MUST 与「账号不存在」「口令错误」的响应一致（相同 HTTP 状态码、相同文案），不得返回 429 或含「被限流」等区分性提示
- **AND** 真实限流原因 MUST 只记录在服务端日志

#### Scenario: 三类失败响应同形

- **WHEN** 分别以「不存在的用户名」「存在但错误的口令」「被限流的请求」发起登录
- **THEN** 三次响应 MUST 返回相同的 HTTP 状态码与相同的错误提示文案
- **AND** 响应耗时 SHOULD 在同一数量级（避免时序侧信道）

---

### Requirement: 数据库故障时业务接口返回 503

当数据库不可用时，业务接口 MUST 返回 503 Service Unavailable，不得把已登录用户判为会话失效。

#### Scenario: 数据库不可用时已登录用户访问业务接口

- **WHEN** 已登录用户（会话有效）请求材料列表、详情或上传等业务接口，且数据库文件不可读
- **THEN** 系统 MUST 返回 HTTP 503
- **AND** MUST NOT 清会话或返回 401 未授权
- **AND** 响应体 MAY 包含通用错误提示（不含内部细节）
